# COI reference database

The COI series is versioned independently from RTBioScan and from the ITS2
series. Its active semantic identity is `rtbioscan_coi_canonical_v1`. The
corrected v1 release candidate has been rebuilt and verified for immutable
publication from this repository under tag
`taxonomy-reference-coi-canonical-v1`. [`v1/`](v1/) is the publication
metadata location; its release hashes are authoritative only when they match
the complete verified bundle at the release tag.

## Construction basis

COI v1 is derived from the deployed
`COInr98_2024Jun_RioNegro_Brazil` BLAST record stream. Its public-data
foundation follows the COInr/mkCOInr approach of Meglécz (2023), integrating
COI records from NCBI and BOLD.

The maintainer attests that those public records and barcode sequences
generated by the project formed the input pool clustered with CD-HIT at 98%
nucleotide identity. CD-HIT retained one input sequence as the representative
of each cluster. The representative's taxID and rendered lineage were then
reassigned to the last common ancestor of all records in that cluster. A
project sequence can therefore contribute to the final taxonomic assignment
without its original accession appearing in the representative FASTA.

That construction history is accepted as maintainer-attested provenance; it
is not presented as a reconstruction from preserved cluster-membership
evidence. The exact pre-clustering input, original command log, and CD-HIT
`.clstr` file are unavailable, so individual historical memberships cannot be
independently replayed. This is a recorded evidence limitation, not an open
release hold. Project-generated COI sequences are retained as ordinary source
records and are not segregated into an unresolved release tier.

## Corrected v1 definition

The corrected release is a deterministic filter of the exact deployed BLAST
OID stream. It preserves every retained record's title, sequence bases, and
relative order. Its combined exclusion policy contains 44 records:

- 5 records with independently confirmed reference-sequence contamination;
- 24 records with cross-family sequence/label conflicts excluded under the
  correctness-first policy; and
- 15 records confirmed by sequence evidence to be outside the COI marker.

The last group comprises one 28S record and mitochondrial COX2, COX3, CYTB,
ATP6, ND1, ND2, ND3, ND4L, ND4, ND5, and ND6 records. The sequence-level
evidence is preserved in the
[`COI v1 marker-scope audit`](audits/coi_v1_marker_scope_audit.md). Corrected
v1 contains 791,389 records and 485,432,240 bases; its exact FASTA, BLAST,
provenance, checksum, and bundle-fingerprint values are recorded in
[`v1/`](v1/).

The distinction between evidence types is retained throughout provenance:
construction history is maintainer-attested, while source-component identity,
record identity, exclusions, counts, hashes, and reconstructed BLAST content
are machine-verified.

## Supporting audits

A comparison with COInr 2024-05-06 showed that every sequence difference
among 791,364 accessions shared with the pre-correction reconstruction was an
exact target-region substring rather than a base substitution or replacement.
The recovered primer pair and selection implementation explain this
transformation; see the
[`COI v1 region-selection audit`](audits/coi_v1_region_selection_audit.md).

The surviving July 18 loose FASTA and derivative BLAST index were shown to be
a malformed post-deployment append, not the source of the deployed July 7
index. They are not reconstruction inputs; see the
[`COI v1 July artifact chronology audit`](audits/coi_v1_july_artifact_chronology.md).

## Versioned construction source

The policy, audit, construction, and legacy-source controls used for corrected
v1 are maintained directly in [`source/v1/`](source/v1/). Its manifest binds
every file by SHA-256. The immutable release tag pins the repository-native
source snapshot together with the resulting release metadata; no mutable copy
in the pipeline repository is treated as the publication authority.

This repository publishes the reference bundle but does not activate it in
RTBioScan. Pipeline activation under a new state identity requires a separate
review; accumulated state from another reference identity must not be reused
or migrated into it.
